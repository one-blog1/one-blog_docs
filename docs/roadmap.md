# 기능 로드맵

최종 확인 2026-10-14 · 운영 0.19 (코드 저장소 `main` 0a95b49)

요구사항(`docs/requirements/`)을 기능 단위로 나눈 목록과 각 기능이 어디까지 왔는지입니다.

## 개발하는 방법 (D-136, D-137)

- **기능 하나 = 스펙 하나.** Spec Kit 순서대로 `/speckit-specify` → `/speckit-plan` → `/speckit-tasks` → `/speckit-implement`.
- specify·plan·tasks는 **단계마다 결과를 보여 주고 사용자 확인을 받은 뒤** 다음 단계로 갑니다. 확인 없이 구현하지 않습니다.
- 스펙에는 관련 요구사항 ID를 적습니다. 코드 저장소에 생긴 `specs/<번호>-<기능명>/`은 기능을 마치면 이 저장소 `specs/`로 옮깁니다.
- 브랜치: `feature/<영어 기능이름>`(예: 댓글이면 `feature/comments`)을 `develop`에서 만들고, 구현·CI를 마치고 사용자가 확인하면 `develop`에 merge합니다. 버전을 올릴 때 `develop`을 `main`에 merge해 배포합니다. 운영 버그는 `hotfix/<이름>`을 `main`에서 만들어 `main`·`develop` 둘 다에 merge합니다.
- 버전과 태그: 기능마다 태그를 붙이지 않습니다. 배포할 때마다 버전을 0.01씩 올리고(D-121), 배포가 성공하면 Actions가 `v0.xx` 태그를 붙입니다(D-120). 자세한 순서는 [releases/README.md](../releases/README.md).
- 테이블은 Crowfoot ERD "One Blog 메인블로그"를 먼저 고치고, 그 기능을 만들 때 Flyway 마이그레이션으로 추가합니다 (constitution IV). 지금 V1~V23, 다음은 V24.
- 6장에서 상태가 "보류"인 항목은 구현하지 않습니다.

## 다음에 할 것

문서에 남아 있는 것만 적습니다. 새 기능은 스펙을 만들 때 여기에 더합니다.

- **보안 미구현 항목**: 같은 IP 로그인 제한(SEC-03)과 HSTS(SEC-12)를 위한 `FORWARD_HEADERS_STRATEGY` 설정, 앱 포트 직접 접속 막기, 운영·개발 DB 분리 확인. 자세한 것은 [보안 진행 현황](security-status.md#미구현).
- **카카오톡 공유** (6.2, D-142): 카카오 앱의 JavaScript 키와 사이트 도메인 등록 뒤. 공유 창 아이콘 줄에 하나 더하면 됨. X·텔레그램·페이스북·기기 공유는 031에서 완료.
- **X 공유 아이콘**: 텔레그램·페이스북은 공식 아이콘으로 바꿈(v0.22). X는 공식 새 로고 파일(X Brand Guidelines PDF의 다운로드 링크)을 받으면 `static/images/share/`에 넣기 (지금은 "X" 글자).
- **소셜 로그인 실제 확인**: 배포 뒤 세 사이트 실제 로그인 확인이 남았습니다(구글은 키 등록 후). [022 tasks](../specs/022-social-login/tasks.md) T010.
- **처리방침·약관 법률 검토**: 공개 전 법률 검토를 받지 않았습니다 (4.6, [0.11 알려진 제한](../releases/v0.11.md#알려진-제한)).

정하지 않아 하지 않는 것: 태그 금칙어(6.4, 보류), 이중화 기술(4.3, 서버를 늘릴 때 정함). [5장](requirements/05-scope-and-open-items.md#아직-정하지-않은-세부-항목).

## 의존 관계에서 주의할 점

처음 001~015를 나눌 때 정한 것입니다. 지금 코드도 이 구조입니다.

- **002의 대표 이미지**: 블로그 대표 이미지(BLG-01)를 받으려고 002에서 `files` 테이블(`post_id`는 외래 키 없이)과 `FileStorage`(SCL-02), 형식·크기 검사(6.3)를 먼저 만들고, 005에서 글 이미지에 재사용하며 `files.post_id` 외래 키를 추가했습니다.
- **004의 카테고리**: `posts.category_id`는 004에서 NULL 칸만 두고, 008에서 `categories` 테이블과 외래 키를 추가했습니다.
- **007 관리자 1차 범위**: 신고(`reports`)와 제재(`sanctions`)는 013에서 만들어, 관리자의 신고 처리(ADM-04), 블로그장 경고·강퇴(ADM-07), 블로그 강제 폐쇄(ADM-02)는 013에서 했습니다.
- **알림 연결**: 003, 006, 007, 009는 알림이 필요하지만 알림은 011이라, 011에서 한꺼번에 붙였습니다. 이후 기능은 처음부터 알림을 붙입니다.
- **04:00 배치**: 폐쇄(BLG-09), 30일 완전 삭제(4.5), 만료 Refresh Token 삭제(D-83)는 모두 같은 배치(012, `shedlock`)입니다. 이후 사진 정리(020, 024, 025)도 이 배치에 붙었습니다.
